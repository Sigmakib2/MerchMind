# Source connector policy

The only built-in network adapter performs generic, read-only HTTPS page retrieval after explicit `--online`. Alibaba and 1688 are not supported integrations. An allowlist entry does not establish a site's permission to automate access. The merchant must check applicable terms and API agreements before enabling a source.

The adapter accepts only exact configured hosts, port 443, and URLs without credentials, query strings, fragments, whitespace or backslashes. It rejects IP-literal URLs and DNS answers containing any non-public address. The TCP connection uses the validated IP address while TLS verifies the original hostname; no second hostname resolution is used for the page connection. Proxy environment variables, cookies and browser sessions are not used. Redirects require manual review.

Each retrieval checks robots.txt first. A missing robots file permits the subsequent fetch; errors or disallow rules produce a typed unavailable/blocked status. Sources with explicit crawl scheduling rules currently require manual review. Requests have size, count and socket-time limits. One bounded retry after a one-second backoff is available for 429/503 within the request budget. Non-200 pages are not treated as successful research. The adapter supports HTML/plain text only. It stores a content receipt hash and unverified title, not a source's claimed price or executable page instructions.

Source status values include `not_fetched`, `retrieved_unverified`, `blocked`, `unavailable`, `unsupported` and `needs_review`. Failure never triggers access bypass or invented listing data. CSV/JSON and confirmed supplier terms are the intended fallback. There is no search API, automatic supplier discovery, price extraction model or multi-domain crawler in this release.

Adding a connector requires a normalized input/output contract, redistributable fixtures, rate and credential handling, source authorization documentation, failure states and tests. New connectors cannot grant purchases, messages, login or uploads through the existing read-only engine. Native DNS resolution and OS-level TLS/socket behavior still depend on the deployment environment; use network-level egress restrictions as an additional boundary for unattended operation.
