# Merchant onboarding

For guided questions that create your own business settings directly, run `merchmind onboard --workspace workspaces/my-store`. An optional `--answers` JSON file supports repeatable intake. See `docs/merchant-journey.md` for the full five-step workflow. The manual demo-template path below remains available.

Run `merchmind init --workspace workspaces/my-store`. Keep real merchant workspaces outside tracked source files. The generated workspace has an internal ignore-all file in addition to repository ignore rules.

Edit `merchant.yaml`: set merchant identity, ISO country and currency codes, source countries, exact approved source hostnames, category restrictions, maximum product mass and target contribution margin. Freight rates must use the merchant base currency. Choose `per_gram` or `fixed_per_unit`; customs are explicitly excluded. Set VAT treatment to `expense`, `recoverable` or `unknown`. Unknown treatment blocks a complete cost estimate. Defaults are examples, not advice about Bangladesh import rules.

Edit `scoring.yaml` to set weights totaling exactly 1, minimum evidence coverage and the sample-test score threshold. `sources.yaml` sets maximum sources, requests per domain, response bytes, report bytes and research duration. The effective source count and duration are the lower of request limits and workspace policy. No paid model/API calls are made by this toolkit; any agent provider's token and spend limits must be enforced by that provider/runtime.

Import your catalog before sales or returns. Accepted fields are listed in the published schemas and sample CSVs. Order identity must be an already-hashed identifier. Emails, names of customers, phone numbers and arbitrary extra columns are rejected. Do not use raw customer identifiers as hashes. Use an offline keyed pseudonymization process if stable linkage is necessary. The application does not use order hashes to infer repeat purchases.

Sales `returned_count` is the return numerator; the separate returns file records reasons and costs and is not added again. Values are gross fulfilled sales before refunds. No net revenue is claimed without refund data. All sales in a workspace must already use the base currency. A given order/product combination must be unique. Aggregate multiple same-product lines in the same order before importing. Import files are snapshots; use a new workspace when revising a snapshot.

Build the profile and review its observations. These are aggregate outcomes, not simulated customers or inferred sensitive traits. A research signal is a merchant-reviewed rating with a rationale and evidence references. The current implementation does not automatically convert profile observations into customer-preference hypotheses.

Supply a request with exact `product_variant_key` and category when known. Record the merchant's safety/legal review and supporting evidence IDs. Pending or unsupported review requires investigation; a blocked review rejects the product. Create a bundle using the `sources`, `quotes`, `comparables` and `signals` shape in `examples/demo-bundle.json`. Review imported evidence before setting freshness to current. Confirm supplier identity, product authenticity, trade terms and sample policy, and include a dated quote validity period. Similar-looking models do not clear the exact-comparable gate.

Prepare the three cost scenarios in the base currency except `unit_price_source`, which uses `fx.source_currency`. The FX rate converts one source unit to the target currency. Cite dated FX evidence, cost assumption evidence and confirmed tax evidence. Include actual product mass, shipping packaging mass and optional volumetric mass in grams; explicit g/kg mass objects can also be normalized automatically. Unknown fields are `null`; known free charges are explicitly `"0"`. Allocate fixed batch/import costs per sellable unit before input. Selling price is net of collected sales tax. Return loss is an explicit expected per-sale allowance, not a raw return percentage.

After research, read the Markdown report, check the evidence manifest and run `research validate`. This recreates the recorded decision at its original time. All outputs remain local. `feedback add --workspace ... --input feedback.json` appends a versioned feedback event referencing an existing report; it never changes the original source evidence or recommendation.
